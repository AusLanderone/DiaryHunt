# DiaryHunt — дизайн (спека)

Дата: 2026-08-27
Статус: одобрено пользователем, готово к плану реализации

## 1. Назначение

Десктоп-дневник **арбитражных сделок** с полностью ручным вводом данных. Аналог StatHunt, но
без парсинга API бирж — все позиции пользователь заносит руками. Приватный, офлайновый,
для личного использования.

Прообраз — Google-таблица пользователя (лист «Сделки»), формулы которой реверс-инжинирены и
проверены на реальных сделках (сходятся до рубля). DiaryHunt воспроизводит её логику с удобными
формами ввода по каждой бирже и добавляет статистику/графики/экспорт.

## 2. Стек

- **Electron** + **чистый JS** (без фреймворков), как в InvestHunt/ArbHunt.
- **Локальный JSON-стор** (файл на диске), без БД. Проще бэкапить и читать глазами.
- Портейбл `.exe` (как InvestHunt: `signAndEditExecutable:false`).

Обоснование: тот же стек, что в существующих проектах пользователя; React/SQLite избыточны для
личного журнала на ~сотни сделок.

## 3. Доменная модель

**Одна сделка = 2 ноги** (MVP строго 2 ноги, как в таблице; 3-я нога — отдельной итерацией позже).

### Хранимая структура (JSON)

```
trade {
  id,             // uuid
  num,            // № по порядку (автоинкремент)
  openDate,       // дата открытия
  closeDate,      // дата закрытия (пусто = открытая сделка)
  type,           // Фьючи / Крипто / RWA (справочник)
  ticker,         // ED, GOLD, SILV... (ручной ввод)
  tag,            // Схождение / Раскор (справочник)
  usdRub,         // курс USD/RUB на момент сделки
  payout,         // Пейаут/перелив, ₽ (ручной ввод, знак +/-)
  adjustment,     // Правка, ₽ (ручная корректировка, опционально)
  comment,        // текстовая заметка
  legs: [         // ровно 2 в MVP
    {
      exchange,   // биржа (справочник): MOEX, FOREX, ...
      side,       // Лонг / Шорт / Спот
      entryPrice, // цена входа
      units,      // количество единиц
      exitPrice,  // цена выхода (пусто у открытой сделки)
      feeRub      // комиссия, ₽
    }
  ]
}
```

Списки-справочники (биржи, теги, типы) хранятся в отдельном редактируемом конфиге (аналог
выпадающих списков в таблице).

### Вычисляемые значения (НЕ хранятся, считаются на лету в `calc.js`)

Проверенные формулы из таблицы:

| Значение | Формула |
|---|---|
| Позиция начало ($), на ногу | `entryPrice × units` |
| Позиция конец ($), на ногу | `exitPrice × units` |
| PnL gross ноги ($) | Лонг: `конец − начало`; Шорт: `начало − конец` |
| Вход спред (%) | `(нога2.вход − нога1.вход) / нога1.вход` |
| Выход спред (%) | `(нога2.выход − нога1.выход) / нога1.выход` |
| Спред итог (%) | `вход_спред − выход_спред` |

**Важно:** спред считается по **порядку ног** (нога1 = базовая биржа, нога2 = вторая), а НЕ по
стороне сделки. Проверено на сделке №3, где стороны в обратном порядке (Шорт/Лонг) — только
формула по порядку ног даёт верный знак. Следствие: форма ввода должна сохранять порядок ног
(какая нога первая/базовая). PnL gross ноги, наоборот, зависит от стороны (Лонг/Шорт).
| PnL net ($) | `Σ gross ног − (Σ feeRub) / usdRub` |
| PnL Руб (₽) | `PnL net × usdRub` |
| % PnL net | `PnL net / Σ(позиция начало)` |
| Чистый профит (₽) | `PnL Руб + payout + adjustment` |

Причина «не хранить»: единственный источник правды — формулы, цифры всегда консистентны и не
«протухают» при правках ввода.

## 4. Экраны

### Журнал (главный экран)
Таблица сделок в стиле исходной Google-таблицы:
- 2 строки на сделку (по ноге), авто-колонки визуально выделены.
- Цветовая маркировка открытых/закрытых сделок.
- Поиск по тикеру/тегу; фильтры по датам/бирже; сортировка по колонкам.
- Строка ИТОГО: суммарный профит.

### Форма сделки (модалка)
- Ввод шапки сделки + двух ног.
- Живой пересчёт спреда и PnL прямо при вводе.
- Добавить / редактировать / удалить сделку.
- Валидация: нельзя сохранить ногу без цены/количества; предупреждение при аномальном спреде.

### Статистика
- Суммарный профит (₽ и $), винрейт, средний профит на сделку.
- Разбивка по тикеру / тегу / бирже / периоду.
- Equity-кривая (график накопленного профита).

### Экспорт
- Выгрузка в CSV, совместимая по колонкам с текущей таблицей.

## 5. Архитектура файлов

Мелкие модули с одной ответственностью:

| Файл | Ответственность |
|---|---|
| `main.js` | Electron main process, окно, IPC |
| `store.js` | JSON CRUD + авто-бэкапы |
| `calc.js` | Все формулы (позиции, спреды, PnL, профит) |
| `journal.js` | Рендер таблицы-журнала, фильтры/сортировка |
| `form.js` | Форма ввода/редактирования сделки, живой пересчёт |
| `stats.js` | Статистика + equity-график |
| `export.js` | Экспорт в CSV |
| `config.js` | Справочники (биржи, теги, типы) |

## 6. Прочее

- **Бэкапы**: авто-копия JSON перед каждой записью (практика из StatHunt, спасала данные).
- **Форматирование чисел**: как в таблице — `$` с 5 знаками для цен, `₽` для профита, `%` для спредов.
- **Открытая сделка**: пустой `closeDate`/`exitPrice`; спред/PnL выхода не считаются, показываем прочерк.

## 7. Границы MVP (YAGNI)

Входит: 2-ногие сделки, журнал, форма, базовая статистика, equity-кривая, CSV-экспорт, бэкапы.

Не входит (позже, отдельными итерациями): 3-я нога и спред для 3 ног, импорт из CSV/API,
мультивалютность сверх USD/RUB, синхронизация/облако.
