# DiaryHunt — раздел «Балансы»

**Дата:** 2026-08-28
**Статус:** дизайн согласован, ждёт реализации

## 1. Задача

Дневник считает профит по сделкам, но не знает, сколько денег реально лежит на
счетах. Нужен раздел, где вручную отмечается текущий объём средств на каждой
площадке, и по этим отметкам строится фактическая кривая капитала.

## 2. Модель данных

Отметка баланса — снимок на дату:

```js
snapshot = {
  id,                      // crypto.randomUUID()
  date: 'YYYY-MM-DD',
  usdRub: number,          // курс на момент отметки
  accounts: [              // произвольное число счетов, минимум один
    { name: 'MOEX',  amount: 1250000, ccy: 'RUB' },
    { name: 'FOREX', amount: 14800,   ccy: 'USD' },
  ],
  comment: string,
}
```

Хранение: `balances.json` в `userData`, рядом с `trades.json`, тем же приёмом
(резервная копия перед записью). Модуль `src/balanceStore.js` повторяет
интерфейс `src/store.js`: `list / add / update / remove / replaceAll`.

Счёт — свободная строка с подсказками из словаря бирж (`config.exchanges`),
чтобы «MOEX», «FOREX», «BYBIT» не приходилось печатать заново. Новая отметка
предзаполняется счетами последней отметки с обнулёнными суммами.

## 3. Расчёты (`src/balances.js`, чистые функции)

| Функция | Что делает |
|---|---|
| `snapshotTotals(snap)` | `{ rub, usd }`: рубли = Σ(сумма × (₽ ? 1 : курс)), доллары = рубли / курс |
| `series(snaps)` | отметки по возрастанию даты, каждая с итогами — источник кривой |
| `deltas(snaps)` | к каждой отметке: изменение к предыдущей в ₽, $ и % |
| `byAccount(snap)` | по счёту: сумма как введена, в рублях и доля от итога |
| `journalLine(snaps, trades)` | вторая линия графика: капитал первой отметки плюс накопленный профит закрытых сделок на каждую дату |

`journalLine` начинается от капитала первой отметки, поэтому расхождение с
фактической линией — это вводы и выводы средств либо неучтённые издержки.

Крайние случаи: пустой список — всё пустое, кривая не рисуется; курс `0` или
отсутствует — доллары `null`, рубли считаются; отметка без счетов — итог `0`.

## 4. Интерфейс

Третья вкладка **«Балансы»** рядом с «Журнал» и «Статистика».

**Шапка:** кнопка **«+ Отметка баланса»**, метрики — текущий капитал в ₽ и $,
изменение с прошлой отметки (₽, $, %), число отметок, дата последней.

**Кривая:** две линии — фактический капитал по отметкам и линия журнала;
переключатель **₽ / $** над графиком. По наведению — дата, обе величины и
расхождение.

**Разбивка по счетам:** доли счетов на последнюю отметку, полосками как в
статистике.

**Таблица отметок:** дата, курс, суммы по счетам, итог ₽ и $, изменение к
предыдущей; строка редактируется и удаляется.

**Форма отметки** (модалка): дата (по умолчанию сегодня), курс USD/RUB с той же
кнопкой «↻ курс», что и в форме сделки, строки счетов (название, сумма,
валюта), кнопка «+ счёт», удаление строки начиная со второй, комментарий.
Итог пересчитывается вживую по мере ввода.

## 5. Интеграция

- IPC: `balances:list / add / update / remove` в `main.js`, `api.balances` в
  `preload.js`.
- Экспорт и импорт базы (`db:export` / `db:import`) включают отметки балансов.
- CSV-экспорт сделок не трогаем.

## 6. Тестирование

- `src/balances.js` — `node:test` на все функции таблицы из §3, включая крайние
  случаи (пустой список, нулевой курс, отметка без счетов).
- `src/balanceStore.js` — по образцу `test/store.test.js`: добавление, правка,
  удаление, устойчивость к отсутствующему файлу.
- E2E: добавить отметку через форму, увидеть её в таблице и на кривой,
  переключить ₽/$, отредактировать сумму, удалить отметку.

## 7. Границы

Не входит: автоматическое получение балансов с бирж, валюты, кроме ₽ и $,
разделение на «свободные средства» и «в позиции», перенос средств между
счетами как отдельная операция.
