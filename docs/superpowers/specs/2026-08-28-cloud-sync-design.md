# DiaryHunt — синхронизация базы через облачную папку

**Дата:** 2026-08-28
**Статус:** дизайн согласован

## 1. Задача

База живёт на одном компьютере. Нужно, чтобы сделки и балансы автоматически
уходили в облако после каждого изменения и подтягивались при запуске, а в шапке
был виден статус синхронизации. Второе устройство должно видеть те же данные.

## 2. Транспорт — одна ссылка

**Правка 2026-08-28:** первая версия синхронизировалась через папку облачного
клиента. По требованию — без папок на компьютере, только ссылка.

Открытая ссылка Google Drive даёт **только чтение**: скачать файл по ней можно,
загрузить — нет, запись требует OAuth. Зато писать по обычному URL можно в
**веб-приложение Google Apps Script**, работающее в аккаунте самого
пользователя: `POST` сохраняет базу файлом на его Google Диске, `GET` отдаёт
её обратно. Пользователь вставляет один адрес вида
`https://script.google.com/macros/s/…/exec`.

Приложение распознаёт вид ссылки (`src/cloudLink.js`):

| Ссылка | Что можно |
|---|---|
| `script.google.com/macros/s/…/exec` | читать и писать |
| `drive.google.com/file/d/…` | только читать, выгрузка отклоняется с пояснением |
| ссылка на Google-таблицу | отказ: это не хранилище базы |
| что-то ещё | отказ с подсказкой, какая ссылка нужна |

Код скрипта приложение показывает и копирует в буфер: Настройки →
Синхронизация → «Как получить ссылку». Настройка разовая, около двух минут.

## 3. Файл синхронизации

На Google Диске лежит один файл `diaryhunt-db.json` — тот же полный бэкап,
что делает `src/backup.js` (сделки, отметки баланса, движения средств,
справочники, настройки), плюс две служебные метки:

```js
{
  ...backup.build(...),      // app, schema, exportedAt, trades, balances, cashflows, config
  syncedAt: '2026-08-28T17:40:12.000Z',
  device: 'DESKTOP-XYZ',     // os.hostname(), чтобы видеть, откуда пришло
}
```

Файл один и перезаписывается: старая версия в облачной папке не хранится.
Перед тем как заменить локальную базу, приложение кладёт её копию в
`%APPDATA%/DiaryHunt/backups/` — это уже принятая в проекте страховка.

## 4. Когда что происходит

Состояние синхронизации хранится в конфиге:

```js
sync = {
  url: 'https://script.google.com/macros/s/…/exec',   // пусто = выключено
  lastPushAt: '…',                // когда последний раз выгружали
  lastPullAt: '…',                // когда последний раз подтягивали
  lastChangeAt: '…',              // когда последний раз менялись данные локально
}
```

**При запуске** — `decide()` смотрит на метки и выбирает одно из четырёх:

| Условие | Решение |
|---|---|
| ссылка не задана | `off` — синхронизация выключена |
| в облаке пусто | `push` — впервые выгружаем локальную базу |
| `cloud.syncedAt > lastPushAt` | `pull` — в облаке версия свежее, забираем её целиком |
| `lastChangeAt > lastPushAt` | `push` — локально менялись данные, выгружаем |
| иначе | `idle` — всё совпадает |

Слияния нет: выигравшая версия **полностью заменяет** проигравшую, как и
условились. При `pull` локальные сделки, балансы и движения заменяются
содержимым файла целиком.

**После каждого изменения** — добавления, правки или удаления сделки, отметки
баланса или движения средств — ставится метка `lastChangeAt` и планируется
выгрузка с задержкой 1,5 секунды (несколько правок подряд дают одну запись).

## 5. Индикатор в шапке

Слева от кнопки «Настройки» — точка и короткая подпись:

| Состояние | Вид |
|---|---|
| выключено | серая точка, «Облако не настроено», клик открывает настройки |
| синхронизировано | зелёная точка, «Синхронизировано 20:31» |
| выгружается | янтарная пульсирующая точка, «Выгружаю…» |
| подтянуто при старте | зелёная, «Обновлено из облака 20:29» |
| ошибка | красная точка, текст ошибки в подсказке |

Подсказка при наведении показывает папку, время последней выгрузки и загрузки,
и с какого устройства пришла последняя версия.

## 6. Настройки → Данные

Поле для ссылки, кнопки **«Подключить»**, **«Как получить ссылку»** (показывает
код скрипта и шаги, копирует код в буфер), **«Выгрузить сейчас»**, **«Загрузить
из облака»**, **«Отключить»**. Под ними строка состояния: что за ссылка, когда
выгружали и загружали, текст ошибки.

## 7. Тестирование

- `src/cloudSync.js` — чистые функции под `node:test`: `decide()` на всех
  ветках таблицы из §4, `stamp()` (метки и имя устройства), `parse()` (битый
  файл, файл чужого формата, файл без разделов).
- Файловые операции — тестом на временной папке: запись, чтение, перезапись,
  отсутствующая папка.
- E2E: включить синхронизацию на временную папку, добавить сделку, убедиться,
  что файл появился и содержит её; подменить файл более свежей версией,
  перезапустить, убедиться, что данные подтянулись; проверить индикатор.

## 8. Границы

Не входит: слияние изменений с двух устройств (только замена целиком),
одновременная работа двух копий приложения с одной папкой, шифрование файла,
история версий в облаке, синхронизация настроек внешнего вида отдельно от базы.
