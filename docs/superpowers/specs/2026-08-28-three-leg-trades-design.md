# DiaryHunt — сделки с тремя и более ногами

**Дата:** 2026-08-28
**Статус:** дизайн согласован, ждёт реализации
**Предыдущая спека:** `2026-08-27-diaryhunt-design.md` (MVP, строго 2 ноги)

## 1. Задача

Дневник умеет ровно две ноги. Пользователь заходит в тройники вида

```
RUS:SI1! / RUS:CR1! / VANTAGE:USDCNH
```

— это синтетический USD/CNH с Мосбиржи против рыночного кросса. Нужен ввод и
корректный учёт сделок с тремя (и, без дополнительной работы, любым числом)
ногами.

## 2. Что уже обобщено, а что ломается

Почти весь `calc.js` написан свёрткой по `legs` и работает при любом числе ног:
PnL по ногам, комиссии, свопы (включая валюту свопа по бирже), объём позиции,
% на капитал, оценка payout, журнал, детали сделки, CSV.

Ломается ровно три вещи:

| Место | Проблема |
|---|---|
| `entrySpread` / `exitSpread` | `const [a, b] = trade.legs` — жёстко две ноги |
| `renderer/form.js` | Две захардкоженные ноги, валидация «обе ноги» |
| `renderer/stats.js` | Разбивка «направление 2-й ноги» подразумевает ровно две |

## 3. Спред: мультипликативная формула

### Решение

У каждой ноги появляется **роль в формуле спреда**: числитель (`mul`) или
знаменатель (`div`).

```
спред = (Π цены ног mul − Π цены ног div) / среднее этих двух произведений
```

> **Правка 2026-08-28 (сверка с таблицей):** сначала формула была
> `Π(mul) / Π(div) − 1`. Импорт реальных сделок показал, что таблица меряет
> спред от середины, а не от знаменателя: на SILV −0,7495% против −0,7467%.
> Симметричная форма выше совпадает с таблицей на парах, а на тройнике даёт
> те же +0,0679%, что и отношение из TradingView — при малых спредах формы
> численно совпадают. Побочная польза: мера симметрична, перестановка ног
> только меняет знак.

`spreadTotal = entrySpread − exitSpread` — без изменений.

### Почему именно так

Формула из TradingView — отношение котировок, а не разность цен. Проверка по
единицам измерения:

```
SI1! (₽/$)  ÷  CR1! (₽/¥)  ÷  USDCNH (¥/$)  =  безразмерная величина ≈ 1
```

Отклонение от единицы и есть спред. На живых котировках:
`85 500 / (11 900 × 7,180) − 1 = +0,07%`.

### Совместимость с проверенными числами

Текущая формула — частный случай новой:

```
(нога2 − нога1) / нога1  ≡  нога2 / нога1 − 1
```

При ролях по умолчанию (нога 1 → `div`, остальные → `mul`) двуногие сделки дают
числа таблицы, включая сделку №3 с обратным порядком сторон. Правило
«спред считается по порядку ног, а не по стороне» сохраняется: роль привязана к
позиции ноги, не к Лонг/Шорт.

### Крайние случаи

- Ног меньше двух → спред `null`.
- Нет ни одной ноги с ролью `div`, либо произведение знаменателей равно нулю →
  спред `null` (в интерфейсе «—»), сделка при этом сохраняется и считает PnL.
- Цена выхода не заполнена хотя бы у одной ноги → `exitSpread = null`, как сейчас.

## 4. Валюта цены ноги

### Решение

У ноги хранится `priceCcy`: `'USD' | 'RUB'`.

- **Значение по умолчанию при вводе:** `USD` для любой ноги.
- **Переключатель валюты виден в форме** и переводится в `₽` вручную — для
  рублёвых котировок вроде `SI1!` и `CR1!`.
- **Миграция:** нога без поля `priceCcy` читается как `USD`.

**Правка от 2026-08-28 (по результату e2e):** изначально умолчанием была валюта
по бирже (`MOEX → RUB`). На прогоне это сломало ввод обычной сделки: у ED и SILV
биржа MOEX, но котировка долларовая, и чистый профит уехал с `+1 044,40 ₽` на
`−3 818,36 ₽`. Умолчание переведено на `USD` — оно верно для большинства ног
дневника, а рублёвые ноги тройника переключаются вручную вместе с ролью.

### Почему не «просто по бирже»

В дневнике уже есть MOEX-ноги с долларовыми ценами: ED `1,15050` и SILV `65,76`
— это доллары. Жёсткий вывод валюты из биржи умножил бы их PnL на курс и сломал
сделки №1 и №3, выверенные до рубля по исходной таблице. Поэтому биржа задаёт
лишь предзаполнение, а истина хранится в сделке.

### Влияние на расчёты

Вводится множитель ноги `k = (priceCcy === 'RUB') ? 1 : usdRub`.

| Величина | Было | Стало |
|---|---|---|
| PnL ₽ | `Σgross × usdRub − Σfee` | `Σ(gross_i × k_i) − Σfee` |
| PnL net ($) | `Σgross − Σfee / usdRub` | `PnL ₽ / usdRub` |
| Позиция начало/конец | `Σ(price × units)` в $ | в ₽: `Σ(price × units × k_i)`; в $ — делением на курс |
| % PnL net | `PnL net / Σпозиция` | то же, обе части в одной валюте |

Для сделок, где все ноги долларовые (то есть для всех существующих), формулы
дают прежние числа — это фиксируется тестом на сделках №1 и №3.

Своп и комиссия не меняются: комиссия всегда в ₽, своп — в валюте биржи ноги
(₽ на MOEX, $ на остальных), как уже реализовано.

## 5. Модель данных

```js
leg = {
  exchange, side,            // как сейчас
  entryPrice, exitPrice, units,
  feeRub,                    // ₽, как сейчас
  swap,                      // в валюте биржи ноги, как сейчас
  role: 'mul' | 'div',       // новое: участие в формуле спреда
  priceCcy: 'USD' | 'RUB',   // новое: валюта цены
}
```

Значения по умолчанию для новой ноги: `role` — `div` для первой ноги, `mul` для
остальных; `priceCcy` — по бирже. Умолчание выбрано так, чтобы двуногие сделки
считались как раньше; для тройника роли выставляются вручную — в примере из §3
это `SI1! → mul`, `CR1! → div`, `USDCNH → div`. Чтение старых сделок: отсутствующий `role`
→ `div` для `legs[0]`, `mul` для прочих; отсутствующий `priceCcy` → `USD`.

Число ног: минимум 2, верхнего предела нет.

## 6. Интерфейс

### Форма сделки

- Ноги рендерятся из массива, а не двумя вызовами. Кнопка **«Добавить ногу»**
  под последней ногой; у ноги, начиная с третьей, кнопка удаления.
- В блоке ноги добавляются два контрола: **роль** (`×` / `÷`) и **валюта цены**
  (`$` / `₽`).
- Над ногами — строка-формула, собранная из ролей: `SI1! ÷ CR1! ÷ USDCNH`,
  чтобы было видно, что именно считается.
- Живой пересчёт и панель итогов — без изменений по составу.
- Валидация: не меньше двух ног, у каждой заполнено количество единиц.

### Журнал

- Строка: чипы всех ног (уже работает при любом числе), спред как есть.
- Раскрытая сделка: в шапку колонок добавляются **Роль** и валюта цены рядом с
  ценой; строка-формула сделки над ногами.

### Статистика

Разбивка «Профит по направлению (2-я нога)» заменяется на **«Профит по
направлению (не-MOEX ноги)»**: ключ собирается из всех ног, кроме MOEX,
в порядке следования. Для двуногих сделок значение совпадает с текущим.

### CSV

К строке ноги добавляются колонки **Роль** и **Валюта цены**.

## 7. Тестирование

Пишется тестами вперёд, `node:test`:

- `entrySpread` / `exitSpread` для двух ног — прежние числа на сделках №1 и №3
  (регресс на выверенных данных).
- Тройник `SI1! ÷ CR1! ÷ USDCNH` — спред `+0,07%` на котировках из спеки.
- Роли: нет знаменателя → `null`; знаменатель ноль → `null`; одна нога → `null`.
- Валюта цены: рублёвая нога не умножается на курс, долларовая умножается;
  смешанная сделка сводится в ₽ верно.
- Миграция: нога без `role` и без `priceCcy` считается как раньше.
- `journalView` и `analytics` — на сделках с тремя ногами (группировка, фильтры,
  разбивки не должны падать).
- E2E: ввод сделки с тремя ногами через форму, проверка спреда и чистого профита
  в журнале; удаление третьей ноги возвращает двуногую сделку.

## 8. Границы

Не входит в эту итерацию:

- автоматическая подстановка котировок ног (ввод остаётся ручным);
- частичные входы и выходы одной ноги (долив/усреднение) — если понадобится,
  это отдельная модель с историей исполнений;
- валюты цены, кроме `USD` и `RUB`.
